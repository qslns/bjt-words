# 한자 카드 작성 지침 (샘플 3 틀 · 950자)

## 누구를 위한 카드인가
- 사용자: 한국인, 일본어 N5~N4 수준, BJT(비즈니스 일본어) 430점을 위해 단어장(1,500 + 기본 885)을 외우는 중. 시험 10/22.
- 이 카드는 단어 카드에서 한자를 누르면 뜨고, 따로 '한자 단원'(앞면 한자만 → 해설)으로도 공부함.
- 사용자가 직접 확인하고 "내가 피드백해도 이보다 잘할 자신이 없다"고 한 샘플이 `gold.json`(日 休 語 確 認)이다. **모든 카드를 이 수준으로.** 먼저 축소판 `preview/gold_s_p0.png`, `preview/gold_s_p1.png`(카드 5장)을 열어 보고 시작할 것.

## 사용자가 좋다고 한 것 / 싫다고 한 것
- 좋음: "쉴 휴 ▸ **사람이 나무에 기대어 쉬는 모습**" — 부품이 그대로 장면 속 등장인물·물건이 되고, 그 장면이 곧 뜻. 읽자마자 그림이 떠오르고 바로 이해됨.
- 싫음(절대 금지):
  - 추상적 연결: "마음(心) 위에 칼날(刃) = 참을 인", "말을 듣고 받아들여요 → 알 인" → **뭔 소린지 모르겠다**고 함. 왜 그 뜻이 되는지가 장면에서 바로 안 보이면 실패.
  - 소리 놀이 연상: "일! 히히 웃는 해님", "나무 옆에 우산 > 검! 켄~ 검사!" → "말이 안 됨, 암기에 방해".
  - 일본어 읽기를 한글로 음차: "니치·지쓰", "켄" 등. 일본어 읽기는 **히라가나로만**.
  - 부수 이름을 대충 쓰기. 사람인변·나무 목·말씀 언처럼 **정식 이름**으로, **가장 작은 부수부터 중간 → 최종** 순서로.
- 가타카나는 어디에도 쓰지 말 것(사용자가 잘 못 읽음).

## 작업 순서 (토큰 아끼며 꼼꼼하게)
사용량 한도가 빠듯하다. 도구 호출 수와 그림 보기를 아끼되 품질은 그대로.
1. 시작할 때 한 번: `cd /home/claude/work/kz && python3 kzc.py info $(cat inputs/<배치>.txt)` — 배치 전체 자료를 한 번에 본다(한 자씩 따로 부르지 말 것). 필요하면 `python3 kzc.py hun 字…`로 부품 훈음 확인.
2. 한 자씩 머릿속으로 장면 후보를 여러 개 떠올리고 '장면 한 줄' 기준을 다 통과하는 것 하나를 고른다. 이 단어장 단어에서 쓰는 뜻을 향하게.
3. **5장씩** 한 번에 써서 배치 파일에 저장(처음엔 Write, 다음부터는 배열에 이어 붙이기 — 파이썬 한 줄이나 Edit). 5장마다:
   `python3 kzc.py validate batches/<배치>.json && python3 preview.py batches/<배치>.json --sheet`
   → 나온 축소판 사진 중 **새로 쓴 5장이 담긴 것만** Read로 열어 그림·글을 확인하고 고친다. (축소판 한 장 = 카드 약 4장)
4. 마지막에 전체 validate 한 번(오류 0). 축소판에서 의심스러운 카드만 `python3 preview.py batches/<배치>.json`(실제 크기)로 확인.

## 카드 형식 (JSON, 배치 파일 = 카드 배열)
```json
{
  "c": "認",
  "hook": "칼날(刃) 같은 말(言)이 가슴(心)을 찔러도 꾹 참고 ‘인정!’ 하는 모습",
  "bridge": "→ 인정하다 · 알아보다 (確認 확인 · 承認 승인)",
  "p1": {"cap": "…", "scene": [ … ]},
  "p2": {"cap": "…", "color": {"言": "blue", "忍/刃": "orange", "忍/心": "purple"}},
  "p3": {"cap": "… → 알 인", "scene": [ … ]},
  "tree": [ {"parts": [{"p": "忍/刃/刀", "n": "칼 도"}, {"p": "忍/刃/丶", "n": "점 주"}], "res": {"p": "忍/刃", "n": "刃 칼날 인"}, "mini": "칼(刀)에 점(丶)을 찍어 ‘날은 여기!’"}, … ],
  "snd": "**忍** = にん → **認**도 **にん** · 한국음 **인** → にん (받침 ㄴ은 ん)"
}
```
훈음·음독·훈독·단어·큰 한자는 앱 자료에서 자동으로 들어가므로 쓰지 않는다. 전체 예시는 `gold.json`.

### 1) hook — 장면 한 줄 (가장 중요)
- 형식: 부품을 구체적인 사람·사물로 놓고 괄호에 그 부품 한자를 붙여 **"~하는 모습"으로 끝낸다.** 예) "사람(亻)이 나무(木)에 기대어 쉬는 모습", "새(隹)가 돌(石)을 콕콕 쪼아 보며 ‘단단하네!’ 확인하는 모습", "입(口) 다섯(五) 개가 모여 말(言)을 주고받는 모습".
- 기준(전부 통과해야 함):
  1. **그림이 바로 그려진다**: 한 장면, 정지 화면 하나로 그릴 수 있다. 사건이 여러 단계로 이어지는 이야기 금지.
  2. **장면 = 뜻**: 장면 속 행동·상태가 곧 그 한자의 뜻(앱 훈음)이다. hook만 읽고도 뜻을 맞힐 수 있어야 한다. "→ 그래서 ~" 같은 설명이 없어도 이해돼야 한다.
  3. **부품이 실제로 그 한자 모양 안에 있다**: 없는 부품을 지어내지 말 것. 주요 부품(2~3개)은 모두 등장시키되, 너무 잘게(한 획짜리 점 등) 다 넣으려고 장면을 망치지는 말 것.
  4. **쉬운 말**: 유아·초등 그림책처럼. 추상어(받아들이다, 의미하다, 개념, 상태 등) 금지. 의성어·짧은 대사('콕!', '인정!', '단단하네!')는 좋음.
  5. 길이 45자 안팎(최대 60). 너무 무섭거나 잔인한 장면, 성적·차별적 내용 금지(認의 '칼날 같은 말' 정도는 괜찮음).
- 그림 글자(상형·지사, 더 안 쪼개짐)는 그 물건을 그린 모습: "네모난 창문 속에 해님이 떠 있는 모습"(日).
- 뜻이 여러 개면 **이 단어장 단어에서 쓰는 뜻**으로 장면을 잡고, 다른 뜻은 bridge에.
- 앱 훈음이 일본어 쓰임과 다르면(예: 欠 = 이지러질 결 → 모자라다) 앱 훈음/단어 뜻 쪽으로.
- 형성자(뜻 부분 + 소리 부분)도 소리 부분까지 장면에 넣어 그림으로 만든다(語의 五+口 → "입 다섯 개"). 소리 부분의 진짜 어원과 달라도 **모양에 근거한** 연상이면 된다.

### 2) bridge (선택)
- hook과 훈음 사이에 한 번 더 이어 줄 때만. "→ 뜻1 · 뜻2 (단어 예)". 필요 없으면 "".
- 예) 日: "해가 한 번 뜨고 지면 하루 → 그래서 ‘날’", 確: "→ 확실하다(確か) · 확인하다(確認)".

### 3) 그림 3칸 p1 → p2 → p3 (각각 그림 + 캡션)
- **p1 = 부품 그림**: 부품을 이모지로("🧍 + 🌳"). 캡션: "사람인변(亻) + 나무 목(木)"처럼 부품 이름(한자). 그림 글자는 그 실물(🌞 "하늘에 뜬 동그란 해"). 3단계짜리(認)는 p1에서 중간 부품 장면을 보여 줘도 됨("가슴(心)에 칼날(刃)이 닿아도 꾹 → 참을 인(忍)").
- **p2 = 부품별로 색칠한 한자**: `"color": {경로: 색}`. 주요 부품마다 다른 색. 캡션은 위치·부품: "왼쪽은 사람, 오른쪽은 나무" / "말(言) + 다섯(五) + 입(口)". 그림 글자는 `"under"`로 한자 밑에 흐린 그림을 깔거나(`{"e":"🌳","s":90,"o":0.25}`), 옛 글자를 그린 scene.
- **p3 = 장면**: hook 그대로를 그림으로. 캡션은 짧은 장면 + **끝은 반드시 "→ 앱 훈음"**("나무에 기대어 쉬는 모습 → 쉴 휴").
- 캡션은 30자 안팎(최대 34). 한 줄에 다 안 들어가도 되지만 짧을수록 좋음.

### 4) tree — 부수로 쪼개 보기 (작은 것부터)
- 단계 배열. 각 단계 = 부품 2~3개 + 결과 + mini(그 단계를 그림처럼 한 줄).
- **마지막 단계 결과는 한자 전체**: `"res": {"p": "", "n": "<앱 훈음 그대로>", "r": "<음독, 히라가나>"}`.
- 중간 결과 이름은 "글자 훈음": "吾 나 오", "忍 참을 인", "隺 새 높이 날 각".
- 부품 경로 `p`: `kzc.py info`에 나온 경로를 그대로. `""`=전체, `"言"`, `"忍/刃/刀"`, 같은 부품이 둘이면 `"木#1"`, `"木#2"`. KanjiVG에 알맞은 묶음이 없으면 획 번호로 `"s:1-3,5"`(1부터).
- 한 단계의 부품은 서로 겹치면 안 되고, 합치면 그 단계 결과와 정확히 같아야 한다(검사기가 확인).
- **어디까지 쪼개나**: 부수(사람인변, 삼수변, 말씀 언, 나무 목, 마음 심, 입 구, 돌 석, 실 사, 쇠 금, 조개 패, 문 문, 수레 차 …)나 그림이 바로 떠오르는 기본 글자에서 멈춘다. 言을 亠+二+口로, 貝를 目+八로 쪼개지 말 것. 반대로 吾(五+口), 忍(刃+心)처럼 **아는 글자 둘로 나뉘는 중간 부품은 쪼갠다**. 보통 1~3단계.
- KanjiVG의 이상한 묶음 이름(𠂊, ⺕, ⺍, 儿<八> 같은 것)은 이름으로 쓰지 말고, 위 단계 부품을 쓰거나 의미 있는 이름을 붙인다.
- 이름 `n`: `info`의 '이름:'(이름표 `radicals.json` → 앱 훈음) 그대로. 모양이 바뀐 부수는 부수 이름(사람인변, 삼수변, 재방변, 심방변, 초두머리, 책받침, 선칼도방, 등글월문, 연화발, 좌부변, 우부방 …) + note "원래 **人**(사람 인) · …". 이름표에 없는 부품은 표준 훈음(`python3 kzc.py hun 字`로 확인). 이름표와 다르게 쓰면 검사기가 '주의'를 띄움 — 이유가 없으면 이름표대로.
- note는 짧게(원래 글자, 별명). r(읽기)은 소리 부분이나 읽기 사슬에 필요할 때만, 히라가나.
- 안 쪼개지는 글자: `"tree": []` + `"basic": "**日**은 더 쪼개지지 않는 기본 글자(그 자체가 부수 **날 일**). 동그란 해를 그린 그림 글자예요."`
- mini: 그 단계를 그림처럼 한 줄(35자 안팎). 추상 설명 금지.

### 5) snd — 소리 줄 (읽기 돕기, 히라가나만)
- 1순위: 소리 부분이 아는 글자이고 음이 같으면 그 사슬: "**五**(다섯) = **ご** → **吾**도 ご → **語**도 **ご**", "**忍** = にん → **認**도 **にん**".
- 2순위: 한국 한자음 → 일본 음독 규칙(이 단어장 사용자에게 가장 쓸모 있음). **아래처럼 확실한 규칙만**, 실제로 맞을 때만:
  - 받침 ㄱ → く·き (확 → かく, 력 → りょく, 역 → えき)
  - 받침 ㄹ → つ·ち (일 → にち・じつ, 결 → けつ)
  - 받침 ㄴ·ㅁ → ん (인 → にん, 심 → しん)
  - 받침 ㅇ → う·い (공 → こう, 생 → せい)
  - 받침 ㅂ → う (업 → ぎょう, 입 → にゅう)
  - 첫소리 ㅎ → 대개 か행 (휴 → きゅう, 해 → かい)
  - 형식: "한국음 **확** → かく (받침 ㄱ은 く로)". 규칙이 안 맞으면 규칙 말을 쓰지 말고 "한국음 **어** → **ご**"처럼만.
- 둘 다 도움 되면 같이(確·認처럼 " · "로 이음).
- 음독이 없는 한자(훈독만)는: "훈독으로 읽어요: **とど(く)** — 음독은 이 단어장에 안 나와요" 식으로.
- 읽기는 앱 자료(info의 음독/훈독)에 있는 것만. `**굵게**` 표시 가능. 가나는 자동으로 일본어 글씨가 됨.

## 그림(scene) 문법 — 칸 하나 = 0~100 × 0~100
| 항목 | 예 | 설명 |
|---|---|---|
| 이모지 | `{"e":"🌳","x":63,"y":52,"s":70,"r":14,"o":0.3,"flip":true}` | x,y=가운데, s=크기, r=회전(도), o=투명도, flip=좌우 뒤집기(선택) |
| 글자 | `{"t":"콕!","x":25,"y":38,"s":13,"c":"red","w":800}` | 효과음·짧은 대사(8자 이내), 가타카나 금지 |
| 더하기 | `{"plus":[50,52]}` | p1의 + |
| 화살표 | `{"arrow":[42,48,56,48]}` | |
| 칼 | `{"knife":[36,44,1,0]}` | 끝(x,y)이 아래를 향하는 칼(기기마다 🔪 방향이 달라서 직접 그림). [x,y,크기,회전] |
| 도형 | `{"rect":[x,y,w,h],"rx":8,"fill":"#FFD84D"}` `{"circle":[cx,cy,r],"stroke":"red","sw":5}` `{"line":[x1,y1,x2,y2],"stroke":"yellow","sw":3}` `{"path":"M…","stroke":"#7A3B00","sw":2.4}` | 간단한 그림 |
| 한자/부품 | `{"k":"","x":50,"y":50,"w":100,"color":"red"}` `{"k":"木","x":70,"y":50,"w":40,"color":{"木":"green"}}` | 그 한자(또는 경로 부품)의 획을 그림 속에 그림 |
- 색 이름: blue green orange purple red gray brown teal pink yellow sky ink (또는 "#RRGGBB").
- 이모지 요령:
  - **Emoji 13.1 이하만**(검사기가 확인). 기기(아이패드/윈도/안드로이드)마다 모양·방향이 달라서, **방향(왼쪽을 본다 등)에 기대는 장면은 피하고** 위치(위/아래/옆)로 관계를 보여 줄 것. 회전은 살짝(±20°)만.
  - 한 칸에 이모지 2~5개. 크기 s는 보통 25~70. 0~100 안에 다 들어오게(가장자리 잘림 확인). 서로 크게 겹쳐 가리지 않게.

## 첫 라운드에서 나온 주의점
- 모양이 王이어도 원래 玉이면 '구슬옥변', 月이어도 원래 肉이면 '육달월', 日 모양이 원래 曰이면 '가로 왈' — `info`의 이름:을 따를 것(검사기가 원래 글자까지 보고 '주의'를 띄움). 장면에서는 모양대로 '왕'처럼 불러도 되지만 tree 이름은 정식으로.
- 표준 훈음이 없는 조각(关, 𡗗 같은 것)에 그럴듯한 훈음을 지어내지 말 것. 아는 글자로 더 쪼개거나, 이름을 'X 모양'(예: '빗장 모양')처럼 솔직하게.
- 한 단계 부품은 2~3개. 획 번호(s:) 묶음을 쓸 땐 그 조각이 실제로 그 부품 모양인지 축소판에서 꼭 확인.
- 칸 그림은 hook 장면을 정말로 보여 줘야 함(p3에 부품 이모지만 나란히 놓으면 실패). 효과음·짧은 대사 글자는 1~2개만.

- 글에 쓰는 부수 글자는 보통 한자로: 辶(⻌ 말고), 阝, 彐, 犭, 爫, 亻, 氵 … (컴파일 때 바꿔 주긴 함). **확장 한자(𠂊 𡗗 𢦏 같은 드문 글자)는 글에 쓰지 말 것** — 아이패드에서 네모로 나옴. 그런 조각은 말로('지붕 모양').
- 쪼개기는 의미 있는 부품 2~3개로. '○○ 모양' 조각을 여러 개 지어내 단계를 늘리는 것보다, 얕더라도 정직한 쪼개기가 낫다.
- 5~6장씩 쓰고, 그 카드가 담긴 축소판(--sheet)만 본다. 실제 크기 미리보기는 축소판에서 이상해 보일 때만.

- 임시 파일(나눠 쓴 조각, 합치는 스크립트 등)은 **반드시 자기 폴더** `/tmp/claude-0/-home-claude-bjt-words/4ecb1043-4c6e-5d36-a7b6-577be7533edc/scratchpad/<배치이름>/` 안에. 공용 폴더 바로 아래에 `merge.py` 같은 흔한 이름 금지, 남의 스크립트 실행 금지(여러 작업이 동시에 돎).
- KanjiVG에서 이름 없는 묶음 안의 부품은 이름 경로로 못 찾음 → `s:` 획 번호로.
- 마지막 결과 읽기 r은 둘 이상이면 "しょく・しき"처럼(각각 앱 읽기에 있어야 함). 음독이 없는 한자는 r 생략.
- p3 캡션은 15~17자 안팎이면 "→ 훈음"이 한 줄에 들어감.

## 품질 점검표 (카드마다)
- [ ] hook만 읽어도 그림이 떠오르고 뜻이 보인다. "모습"으로 끝난다. 추상어·소리 놀이·음차 없음.
- [ ] hook의 부품이 실제 모양 안에 있고, 괄호 한자가 맞다.
- [ ] p3 그림만 봐도 장면이 보인다(이모지 배치가 장면을 실제로 보여 줌). p3 캡션 끝 = "→ 앱 훈음".
- [ ] tree: 작은 것 → 중간 → 최종. 이름이 정식(이름표/훈음). 부품 겹침·빠짐 없음(검사기). mini가 그림처럼.
- [ ] snd: 읽기는 히라가나, 앱 읽기와 일치, 규칙이 실제로 맞을 때만.
- [ ] 가타카나 0. 오타 0. 존댓말·반말 섞지 말고 짧은 해요체/명사형(샘플처럼).
- [ ] 미리보기 사진에서 잘림·겹침·넘침 없음.
