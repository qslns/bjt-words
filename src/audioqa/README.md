# 음성 받아쓰기 검사 도구 (10/21~22)

목적: 앱 음성(한자 읽기·대표 소리·단어·예문)이 화면 읽기대로 소리 나는지 사람 귀 대신 인식기 두 개로 전수 확인.

- 음소 인식기: HuggingFace `prj-beatrice/japanese-hubert-base-phoneme-ctc-v4` (ReazonSpeech로 학습, pyopenjtalk 음소). `export_onnx.py`로 ONNX로 내보내 ONNX Runtime으로 계산(torch보다 2배 빠름, 결과 같음). `phon.py`
- 단어 인식기: sherpa-onnx `sherpa-onnx-zipformer-ja-reazonspeech-2024-08-01`(GitHub 릴리스) int8. `reazon.py`
- 짧은 소리(한자 읽기·단어)는 앞뒤에 같은 목소리 'これは … です'(pre_*/post_*.wav)를 붙여 인식(단독 한 박은 인식기가 첫 자음을 헷갈림). `qa_ctx.py`
- 예문은 긴 쉼(0.35초+)에서 잘라 조각마다 인식(`logits_chunked`): 한 번에 넣으면 쉼 뒤 문장을 통째로 빠뜨림.
- 기대 음소: 후리가나 구간은 그 가나 그대로, 나머지는 pyopenjtalk(조사 は→わ, 숫자). `sent_exp.py` / `kana.py`
- 판정: 편집 거리 정렬로 구간마다 들린 음소 → 다르면 CTC 점수 차(mg)로 얼마나 확실한지. 두 인식기가 다르게 들으면 Δ(정답-다른 쪽 점수)로 판정(`dispute.py`).
- 고치기: 넣는 글을 바꿔 후보 여러 개(그냥 글·가타카나·「」·속도·목소리) → 두 인식기 다 통과한 것 중 우선순위 첫 번째(`consensus.py`·`fixgen.py`·`sfix.py`).
- 교훈: は로 시작하는 말을 히라가나로 넣으면 조사로 읽어 わ가 됨(はこ→わこ, はいる→わいる, はつか→わつか) → 가타카나로. 나나미는 단독 'てん'을 'せ'로 읽음 → 게이타. 「」로 감싸면 は가 わ가 되는 읽기가 있음.
- 인식기 버릇(그대로 둔 것): コミュニケーション·マニュアル(ミュ→ミ), 품질·紛失·会議室(しつ→しゅつ/じゅつ, 게이타), 期日(じつ→じゅつ), 見本市(にほんいち), 게이타 'が、' 쉼에서 'ある', バッグ(グ 무성화).
