## 음성
- 엔진이 언제든 막힐 수 있음(10/10) → 대체 경로(Azure 같은 목소리) 준비. 사용자는 구글·애플 음성을 듣기 불편해 함.
- 기기가 음성을 영구 저장 → 같은 주소로 파일만 바꾸면 옛 소리가 계속 남 → 바뀐 파일은 ?v=해시.
- 오독 고치려고 가나로 바꿔 넣었더니 새 오독: **は로 시작하는 말을 히라가나로 넣으면 조사로 읽어 わ**(はこ→わこ, はいる→わいる, はつか→わつか) → 가타카나로. '…はわたくし'의 は가 사라지는 것도.
- 「」로 감싸면 오히려 틀리는 읽기가 있음. 나나미는 단독 'てん'을 'せ'처럼 읽음(앞에 0.14초 바람 소리) → 게이타.
- edge-tts는 같은 글이면 늘 같은 소리 → 고치려면 넣는 글·목소리·속도를 바꿔야 함.
- 같은 목소리로 만든 후보와 비교(MFCC)하는 방법은 유성/무성·한 박 이상을 못 잡음 → 인식기 두 개 받아쓰기로 바꿈. 짧은 소리는 'これは … です' 사이에, 예문은 쉼에서 잘라서.
- 바꾼 파일은 반드시 다시 받아쓰기로 확인하고 배포 뒤 라이브 md5 확인.

## 화면·조작
- **첫 touchmove를 막으면 클릭이 취소돼 탭이 가끔 안 먹음**(10/15) → body 고정·끌기 막기 금지. 시험에 손가락 흔들림 탭 검사가 있음.
- 효과·애니메이션은 사용자가 싫어함('가볍고 잘 되는 것만'). 아래 버튼 자리 고정(알고있음·다음은 늘 오른쪽).
- 탭 잠금 300ms → 시험 스크립트는 탭 사이를 350ms 넘게 띄워야 함(11/9에 빠르게 눌러서 시험이 거짓 실패).

## 도구·환경
- **접기 안에 접기**(11/13): `.gf[open] .fold`처럼 자손 선택자를 쓰면 바깥 접기가 열릴 때 닫힌 안쪽 접기도 '접기 −'로 보임 → `.gf[open]>summary .fold`처럼 자기 summary만. 스크린샷을 눈으로 봐서 잡음(시험은 통과했었음).
- 닫힌 `<details>` 안 요소도 지금 크로미움에선 `getClientRects()`가 비지 않음(content-visibility) → 보이는지는 `el.checkVisibility()` 또는 playwright `>> visible=true`로.
- `git pull --rebase`는 커밋 안 한 변경이 있으면 거부함 → **커밋 먼저 → pull --rebase → push** 순서.
- rsync가 없는 컨테이너가 있음 → `apt-get install -y rsync`. src 갱신 rsync는 `shot_*.png`(시험 스크린샷)·`expansion/*.md`(문서는 저장소에서만 고침)를 빼야 함.
- 앱 시험 개수는 같은 빌드에서도 무작위 표본 때문에 1개씩 달라짐(228·229) → 기대값을 바꿨으면 개수보다 검사 이름 목록으로 비교.
- 진도 보존 시험에서 ★를 누를 카드가 이미 약점이면 ★가 '빼기'가 됨 → 누르기 전 상태와 비교(무작위 순서 때문에 가끔 실패했음).
- **백업에 '빌드가 읽는 파일'만 넣었더니 제작 도구가 사라짐**(루비·풀이 생성기, 기본 카드 파이프라인 일부 — 11/13 발견). 공개해도 되는 제작 도구는 바로 커밋. 빼는 건 모의 유래 자료·키뿐.
- 컨테이너가 바뀌면 시험 서버·`app/test/audio` 연결·playwright 연결이 사라짐 → HANDOFF 3절대로 다시. playwright를 npm ci로 새로 깔면 브라우저 버전이 어긋남.
- 브라우저 경로가 바뀜(chromium-1194 → 1243) → 시험 파일은 `PW_CHROME` 환경 변수로.
- 4MB 문자열에 difflib → 멈춤. 바이트 위치 비교로.
- sed 치환 문자열에 `&`가 있으면 파일이 깨짐 → 파이썬이나 Write로.
- 내려받은 자료는 따로 폴더 + `python3 -I`, 경로는 인자로.
- 분석 입력 글 다시 받기: BSD `github.com/tsuruoka-lab/BSD`(→ bsd2txt.py) · chABSA는 HuggingFace `jarvisx17/chABSA`의 chABSA.csv(원래 S3 링크는 죽었고 TheFinAI 판은 로그인 필요) · 드릴 문장은 qslns.github.io/bjt-grammar·/keigo 페이지(→ html2txt.py) · JLPT 목록 `github.com/jamsinclair/open-anki-jlpt-decks` src/n5~n1.csv. 빈도 매칭은 fugashi + unidic-lite 표제형, 긴 것 먼저.

## 진행 방식
- 사용자는 계획을 자주 바꾸고 바로 취소하기도 함 → 큰 작업은 시작 전에 범위 확인, 언제든 되돌릴 수 있게 작은 커밋.

- 공식 모의는 사용자가 다시 풀 수 있어 내용 비밀. 문서도 '스포 없음'(집계만).
- 이해 안 되는 건 작업 전에 질문(사용자 요청). 단, 사용자가 없을 땐 가장 합리적인 해석으로 진행하고 그 해석을 기록.
